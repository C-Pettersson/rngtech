# Current Implementation Matrix

Status: Implemented

This page tracks the current code surface. It is the implementation-oriented counterpart to the broader design pages, which may also describe planned systems.

Use this page to answer:

- Is this content registered in code?
- Is it craftable or data-driven?
- Does it have a block entity, menu, screen, or capability?
- Does it currently use RPG traits or refinement?

Planned pages such as component upgrades and broader named behavioral modifiers are design targets, not current registered gameplay unless listed below. Current component progression tops out at Stage 8 Exotic; Component Stages 9-10 are not registered content.

The material catalog is code-backed. It registers RNGTech-owned item ids, ore blocks, raw material drops, textures, models, language entries, tags, creative-tab entries, enablement config, manual early plate forming, default ore world generation, and a small vanilla-backed recipe surface. Vanilla-owned forms such as Iron, Copper, Gold, and Netherite ingots, ores, raw materials, nuggets, and storage blocks are mapped into tags instead of being duplicated as RNGTech items where vanilla already provides them.

Machine, chassis, component, and Battery Cell numeric identity is authored as base stat profiles before modifiers are applied. Machine and chassis profiles are resolved through `MachineBaseStatCatalog`; installable component and Battery Cell profiles are resolved through `ComponentBaseStatCatalog` before their stored rolled affixes are merged into a host machine. `MachineImplicitCatalog` keeps fixed behavior identity and nonnumeric item identity. Fixed identity is re-derived from the concrete item or block, is shown separately from rolled affixes, and is not removable by Nullifier Coil, Affix Forge refinement, or Debug Reroller. Rolled affixes are now named definitions with an affix id, modifier group, slot, tier range, and one or more effects. Modifier groups prevent duplicate compatible families from coexisting during normal rolls, Affix Forge additions, transmutation, rerolls, and Expansion Crystal slot filling. Most behavior flags are fixed identity traits and currently include fuel governance/reserve behavior, alloy-blend smelting speed, battery charge balancing, burst release, cell leakage damping, power grace, residue screening, output guards, thermal buffering, and side fluid output. `BULK_SPEED` is a rollable behavior flag for eligible processing-machine blocks and ramps processing speed by `1%` per completed process, up to `100%`; it shares the `processing_speed` modifier group with processing-speed affixes and Overclocked. Balance Mode is a rollable Battery Chassis prefix that enables `CHARGE_BALANCER` and evenly fills or drains installed cells. Crusher Frame prefixes can enable `OUTPUT_GUARD` on rolled Crusher machines, and Crusher Throughput prefixes add `BATCH_SIZE`.

Processing profiles can roll work-specific speed affixes such as Crushing, Smelting, Pressing, Melting, Alloying, Calibrating, Screening, Assembly, and Disassembling. Powered processing profiles can roll the compound Overclocked suffix, which increases processing speed and increases energy usage. Eligible processors can roll Instant Process, which completes processing immediately only when the machine can pay the full up-front processing cost, and item-output processors other than the Component Recycler and its Disassembly Head can roll Super Output, which adds one extra copy of the base stackable output without multiplying deterministic `OUTPUT_AMOUNT`.

Optional Jade integration is present through `com.rngtech.compat.jade` and remains an optional dependency: Jade is `compileOnly` for API access and `localRuntime` for dev testing. When Jade is installed on both sides, `rngtech:machine_state` syncs compact server-owned state for every placed block entity that implements `MachineInfoProvider`: the processing machines, generators, Compressor Tanks, solar blocks, Exotic Affix Forge, wooden and silica-gel machines, and Forestry Cart Station. The overlay shows translated state, the machine's own status text when it is not running, progress, FE, fuel, recipe gates, Gear summaries, output notes, storage-cell counts, live FE telemetry, connector caps, bottleneck warnings, and sneak-only refinement summaries from the machine-owned `MachineInfoSnapshot` read model. `rngtech:machine_tanks` lists each machine tank exposed through `PurgeableFluidStorage` with its label, fluid, amount, and capacity. The default overlay is compact: it hides idle progress, live FE telemetry, satisfied level and heat gates, and output notes that repeat the state line. Jade's Show Details key reveals them. RNGTech machines suppress Jade's generic energy bar because the energy line already carries stored FE and FE/t. Machine state is also proxied when Jade targets a Universal Connector or cable-side connector attached directly to one of those machines. Universal Connector targets also expose their own live last-tick FE in/out and connector cap. The existing `rngtech:cable_connector_target` Jade provider still handles cable-side connector names and icons.

Optional GuideME integration is data only: the mod jar ships the data-driven guide `rngtech:guide` from `src/guide/resources`, generated from the player wiki by `tools/rngwiki/guideme.py` (see [Wiki Authoring](wiki-authoring.md#in-game-guide)). GuideME is declared as an optional dependency in `neoforge.mods.toml` and is `localRuntime` for dev testing; there is no RNGTech code against its API, and without GuideME the guide files are never read.

Optional AE2 and Refined Storage bridge integration is present through `com.rngtech.compat.ae2` and `com.rngtech.compat.refinedstorage`. AE2 is `compileOnly` against the API with the full mod on `localRuntime`; Refined Storage is `compileOnly` with the full mod on `localRuntime`. Universal Connectors now have a Bridge tab with a dedicated bridge channel and one Network Connector slot. Installed AE2 and Refined Storage Network Connectors expose the matching third-party network capability only when the required mod is loaded, and only connect matching same-mod endpoints on the same RNGTech bridge channel. The bridge does not convert AE2 to Refined Storage and does not expose external storage to RNGTech.

Fluid purge cleanup is code-backed for RNGTech machines that own real stored tanks: Bio Generator take-off tanks, Corrosion Cell, Melter, Component Assembler, Cavitation Generator, Algae Photobioreactor, Wooden Composter, Wooden Dehumidifier, Silica Gel Dehumidifier, Gas Chemistry machines, Ammonia Synthesizer, Fuel Cell, and Fluid/Compressor Tanks. The craftable `rngtech:purge_bucket` and Process-tab purge buttons void up to `1000 mB` per action and never recover fluid. Input-tank purges reset active work state where the machine tracks recipe progress. Debug sinks/sources, cables/connectors, transient network transfer state, and third-party fluid handlers are not purge targets.

## Material Catalog

The material catalog is defined in `src/main/resources/data/rngtech/materials/catalog.json` and loaded by `com.rngtech.content.material.MaterialCatalog`. Ore block scope and generation profiles are defined in `src/main/resources/data/rngtech/materials/ore_catalog.json` and loaded by `com.rngtech.content.material.OreCatalog`. It registers material forms, ore blocks, generic recipe forms, and non-stage reagents. Current counts and default family settings are generated in [Material Catalog Coverage](material-catalog-coverage.md); keep those counts in that one location.

Support files provide item and block models, blockstates, loot tables, language entries, common `c:` item and block tags, RNGTech grouping tags, the aggregate `rngtech:materials/family/alloys` material-family group, manual early plate recipes, generic Casing, Machine Frame tier, and Bus Bar recipes, and the vanilla-backed material form recipes. The generated coverage table is [Material Catalog Coverage](material-catalog-coverage.md).

Material family enablement is controlled by the common config `materials.<material>`. Disabled RNGTech-owned family forms remain registered for save compatibility, but are hidden from the RNGTech creative tab and excluded from recipes guarded by the `rngtech:material_enabled` condition.

RNGTech-owned ore ids such as `rngtech:tin_ore` are real block items, with deepslate variants such as `rngtech:deepslate_tin_ore`. Default Overworld generation is enabled for Tin, Zinc, Nickel, Lead, Silver, Aluminum, Osmium, Titanium, Tungsten, Platinum, and Naquadah. Normal mining drops `rngtech:raw_<material>` with Minecraft's Fortune ore-drop scaling; Silk Touch drops the ore block. Raw drops are tagged as `c:raw_materials/<material>` and can be crushed or smelted through tag-backed recipes. Alloy families such as Bronze, Steel, Invar, Sparksteel, Arclite, Tungstensteel, Nullite, and Aethergold exclude ore and raw forms entirely; they are reached through ingredient chains and Alloy Furnace recipes instead of terrain ore. Worldgen is controlled by `worldgen.ores.enabled`, per-material `worldgen.ores.<material>.enabled`, and biome modifiers such as `data/rngtech/neoforge/biome_modifier/ore_tin.json`; pack authors can disable those modifiers with `neoforge:none` and drive large deposits from `c:ores/<material>` block tags. When JEI is installed, the Ore Generation category shows the configured source ore profiles with block variants, raw drop, depth, attempts per chunk, vein size, air-exposure discard, ore hardness, config state, and biome modifier id. Ore hardness gates are block tags under `rngtech:ore_hardness/level_<n>` for RNGTech ores and the listed vanilla ores; `rngtech:ore_hardness/common/level_<n>` holds each metal's optional `c:ores/<material>` tag and counts only when `worldgen.ores.commonOreTagHardness` is on (default off), so other mods' ores share the gate only by pack choice. Source-ore Crusher recipes match `c:ores/<material>`, split by `c:ores_in_ground/deepslate`. Modular Picks and Hammers reach their head's level; other items use the `rngtech:ore_reach` item data map or else `worldgen.ores.vanillaToolBridgePolicy` applied to the vanilla tier they harvest at (default `TIER_LADDER`: stone 1, iron 3, diamond 6, Netherite Pickaxe 8). Items in `rngtech:restricted_tools` (stone through netherite pickaxes, axes, and shovels) follow `restrictedTools.mode` (`NORMAL`, `WEAKENED`, `USELESS`), and `restrictedTools.vanillaRecipesEnabled` gates conditional overrides of their vanilla recipes. Bronze starts with the Copper Dust, Tin Dust, and Coal Dust blend recipe; the Alloy Furnace adds an improved blend recipe and a later direct-ingot recipe. See [Alloy Furnace](https://c-pettersson.github.io/rngtech/alloy-furnace/) for the recipe progression. Alloy dusts are not default survival progression sources.

## Gear Tabs

Gear compatibility is backed by a shared machine-first catalog. When JEI is installed, the `Machine Gear` category lists each machine's Gear slots and valid component classes, and JEI usage lookup from a component shows compatible machines. Without JEI, hovering an empty active Gear slot in a machine screen shows the expected component class; holding Shift expands concrete valid item examples.

Current placed-machine Gear tabs are:

- Affix Forge: the main forge screen exposes three reusable upgrade slots. Affix Lens Array unlocks modifier lens focus items, Affix Modifier Socket unlocks modifier crystals, and Affix Resonance Matrix unlocks Greater Affix Upgrader plus ascension/reroll/expansion/null crystal operations. Installed upgrades are saved with the block and update placed visuals.
- Crusher: Gear tab exposes the crush-head slot and Battery Cell slot. A valid Crush Head is required for processing and normally must not exceed the placed chassis stage; Component Stage Support Mastery nodes can raise that acceptance ceiling by one per allocated Component Mount, while Precision Jaw Mount still requires an exact chassis-stage head. Staged heads provide hardness levels `1-8`; recipes whose `required_processing_level` is above the active head still process, but each missing level increases processing time, raises total FE cost, and adds a cycle-start jam chance. The installed Battery Cell provides most Crusher FE storage. Without a Battery Cell, the Crusher keeps only its small internal buffer and applies a production penalty that Crusher Battery Link prefixes and the much weaker Scuffed Crush Head prefix can reduce, while the Cell Bypass Mastery keystone eliminates it. Crusher Mastery is machine-owned chassis progression: completed recipe jobs grant `machine_xp`, level grants passive points, and nodes can add stats, constrain Gear slots, mute machine sounds, support higher-stage Crush Heads, or add Batch Size through the Dense Batching keystone.
- Furnace: Stage 0 has one saved component slot for future Furnace-compatible `MachinePartItem` stacks and burns standard fuel from Process. Electric Furnace chassis add a Gear-tab Battery Cell slot, accept Heat Cores up to the chassis stage, and receive FE through block energy capability. Every Furnace has one Gear slot; the Lead Furnace's four paired input/output lanes share its one Heat Core, and cores saved in its three retired slots move to an adjacent inventory or drop when a player is near. Each lane locks a `BATCH_SIZE` batch from its input stack at cycle start, scales cycle time by `BATCH_OVERHEAD`, and its heat engine charges each item's recipe heat (FE, or Stage 0 burn time) plus wall loss; a larger batch takes a larger load dip at cycle start. A failed batch turns every item into the failure output. Furnace recipes can require target heat and temperature stability, then Stage 4+ failure-bearing recipes can turn underheat, overheat, instability, and sensitive post-start FE drops into local failure strain. Installed Heat Cores on electric Furnace chassis contribute the active high-heat and heat-control stats. Furnace Mastery is machine-owned chassis progression: completed positive-XP recipes grant `machine_xp` once per completed lane after recipe-band falloff, level grants passive points, and nodes can add heat, speed, thermal-control, efficiency, or Mute Machine Sound effects. Quench Protocol halves temperature-derived failure strain without reducing power-drop strain, and Closed-Loop Recuperator refunds `5%` of adjusted electric recipe FE to the internal buffer after successful output.
- Alloy Furnace: Gear tab exposes one required Heat Core slot, one required Alloy Crucible slot, one optional Battery Cell slot, and one optional Servo slot. Heat Cores provide the active heat gate, Alloy Crucibles provide input-slot count and mixing control, Servos add optional control stats, and Battery Cells add portable FE storage. Alloy Furnace recipes warm up to target heat before progress starts and can opt into Stage 4+ failure strain and power sensitivity. A `BATCH_SIZE` batch crafts whole recipe sets, limited by the input slots and output room, with the same Batch Overhead time scaling, per-set heat and XP, load dip, and whole-batch failure as the Furnace.
- Battery Chassis: Gear tab exposes material-defined Battery Cell slots plus active slots from Additional Battery Slots rolls. Installed cells provide the stored FE, and chassis capacity prefixes scale installed-cell capacity only while those cells remain in the chassis.
- Exotic Affix Forge: Gear tab exposes one optional Battery Cell slot. The machine receives FE through block energy input, stores `2,000,000 FE` internally, and uses the installed cell as portable backing storage for high-cost refinement operations.
- Component Assembler: Gear tab exposes one optional Battery Cell slot. The Process tab owns four item inputs, a dry-electrolyte or fluid-container slot, an assembly-fluid tank, and a four-slot output rack. Recipes are authored through the compatibility `rngtech:battery_assembly` id; Primed Cell Core recipes consume Electrolyte Solution, Servo and frame-coupling recipes consume Lubricant, and final-cell recipes consume the stackable core and roll final Battery Cell traits on completion.
- Solid Fuel Burners: Gear tab exposes one Heat Core slot, one Battery Cell slot, and one Fuel Box slot. Heat Cores and Fuel Boxes contribute generator stats; the installed Stage 0-4 Battery Cell is the generator's FE buffer.
- Bio Generator: Gear tab exposes one Battery Cell slot, one Bio Chamber slot, and two Gas Line slots. The installed Stage 0-3 Battery Cell adds portable FE storage, the Bio Chamber contributes per-stack fuel efficiency and ingredient-aware crop or biomass power prefixes, and the Gas Line slots take Fluid Pumps or a Biogas Membrane for the Methane take-off.
- Algae Photobioreactor: Gear tab exposes one Bio Chamber slot. It is a non-generator support processor with input-only water and carbon-input tanks accepting Carbon Exhaust, Syngas, or Carbon Monoxide, vertically stacked container input/remainder rows, an algae output slot that accepts manual and sided Algae Biomass pre-stacking, a recipe light gate, and Bio Conversion output scaling from the installed chamber's fuel-efficiency contribution. An optional Urea slot (automation input) spends one `rngtech:urea` to grow the next 4 biomass at twice the speed, with water and carbon per biomass unchanged.
- Wooden Dehumidifier: no Gear tab, no RPG traits, no refinement, and no FE. Its structure frames are world blocks counted by the controller rather than installed equipment.
- Silica Gel Dehumidifier: no Gear tab, no RPG traits, no refinement, no FE, no container slots, and no ambient humidity checks. Its fixed two-casing column is world structure, while lane throughput is driven only by `rngtech:desiccant_absorption` recipe matches and bead availability.

The controller aggregates connected Solar Panels inside its effective range, shares overlapping panels with other controllers, stores generated FE internally or in the installed cell, and exports FE through side energy capability with no machine-side cap; the attached Universal Connector's Energy Connector tier limits export.
- Potential Reactor: Gear tab exposes one required Reactor Chamber slot, one optional Recovery Filter slot, and one optional Containment Lining slot. Reactor Chamber `PROCESSING_LEVEL` gates `rngtech:potential_reactor` recipe `minimum_material_stage`; Recovery Filters enable residue output; Containment Linings improve stability. The same block is currently the Energy Recycler compatibility path for RPG-bearing inputs and emits `rngtech:recycling_stripped` outputs.
- Corrosion Cell: Gear tab exposes optional Battery Cell, Fluid Pump, and Cathode slots. The installed Cathode's stage sets the highest Anode the cell can burn, and its rolled stats apply to the cell. The Process tab owns plate/anode/scrap input, electrolyte item input, an electrolyte-fluid tank, and residue output. Recipes are authored through `rngtech:corrosion_cell`; `125 mB` of stored Electrolyte Solution can substitute for one dry electrolyte item, and an installed Fluid Pump enables fluid filling on every face with its effective `FLUID_TRANSFER` rate. The Process tab's load gauge sets the share of rated current the cell draws; rated load reproduces the recipe, and lighter loads lengthen the cycle and raise FE per fuel. The Stage 4 machine pauses when residue output or FE storage is full, mid-cycle without losing FE. There is no sludge fluid.
- Cavitation Generator: Gear tab exposes required Cavitation Rotor and Collapse Nozzle slots plus optional Heat Core, Battery Cell, and Stage 6+ Servo slots. The nozzle slot accepts ordinary Steel through Exotic Collapse Nozzles plus Cavitation-only `rngtech:nitrogen_separation_nozzle`. The Process tab owns the throttle on its rotor speed gauge, the fluid-container slot, nitrogen output tank, and pitted-rotor output. Recipes are authored through `rngtech:cavitation`; optional rotor/nozzle recipe ingredients can select gear-specific outputs, rotor stage gates recipe eligibility, pressure is recipe-authored display/balance data, heat strain is local to the machine, and rotor wear is stored on the installed Cavitation Rotor stack. Fully worn rotors eject the generic `rngtech:pitted_cavitation_rotor`, which has a Stage 5 Component Recycler salvage recipe instead of preserving source rotor material. Side FE export has no machine-side cap; the attached Universal Connector's Energy Connector tier limits it, and generated FE that storage cannot hold is vented. The nitrogen water recipe requires `rngtech:nitrogen_extraction_rotor` plus `rngtech:nitrogen_separation_nozzle`, outputs Nitrogen before effective `OUTPUT_AMOUNT`, and keeps FE generation lower than the generic water FE recipe. `rngtech:aethergold_cavitation_rotor` is a Stage 7 burst rotor that raises generation and processing speed while wearing out quickly; its burst needs a Sparksteel or better Energy Connector on the attached Universal Connector. It is a powered support processor, not a generator.

The machine consumes ammonia or hydrogen, one at a time in its single fuel tank, through `rngtech:ammonia_power_cycle`, stores generated FE internally or in the installed cell, exports FE from top or side faces, and emits recipe residue to the Process output slot.

Nullite Servo Auto Purge applies to Gas Chemistry output tanks when those tanks already contain matching fluid.

Recipes are authored through `rngtech:vacuum_collapse`; Void Chamber stage gates recipe eligibility, stability gates high-risk recipes, lower-stage nozzles add `+1.0` instability pressure per missing recipe stage, and residue handling can require the stabilizer. Crude Press requires Heat Core and an active Mold while Servo is optional; Steel Press requires Heat Core, Servo, and an active Mold. Heat Cores from Iron through Titanium enable the forming bed and gate forming recipe temperature; Stage 8 Exotic exists but remains above the Metal Press Stage 6 Heat Core cap. Heat Core temperature, Crush Head `PROCESSING_LEVEL`, and Fluid Pump presence gate `rngtech:melter` recipes; the Battery Cell provides portable FE storage; Servo improves speed/control; Fluid Pump enables output container filling and side fluid extraction.

Steel+ Compressor Tanks expose one Battery Cell slot and four Servo slots, require one valid Battery Cell, at least one valid Servo, and FE to move fluid between loose and compressed stores, and expose FE input only without FE extraction.

## Trait and Refinement Boundaries

Current refinement targets are:

- Machine block items backed by `MachineBlockItem`.
- Placed Crusher and Furnace machines through their Refinement tabs. Electric Furnace chassis use the electric furnace modifier profile.
- Placed Alloy Furnace chassis through their Refinement tabs.
- Placed Battery Chassis blocks through their Refinement tabs.
- Placed solid fuel-burning generator chassis blocks through their Refinement tabs.
- Placed Bio Generator blocks through their Refinement tabs.
- Placed Solar Array Controller blocks through their Refinement tabs.
- Placed Potential Reactor blocks through their Refinement tabs.
- Placed Corrosion Cell, Cavitation Generator, Coal Gasifier, Syngas Combustor, Steam Methane Reformer, Ammonia Synthesizer, Fuel Cell, and Vacuum Collapse Generator blocks through their Refinement tabs.
- Placed Crude and Steel Metal Press blocks through their Refinement tabs.
- Placed Resonance Calibrator chassis through their Refinement tabs.
- Placed powered Component Recycler chassis through their Refinement tabs. Crude Recycler is not a refinement target.
- Placed Component Assembler blocks through their Refinement tabs.
- Placed Melter blocks through their Refinement tabs.
- Placed Fluid and Compressor Tanks through their Refinement tabs.
- Machine parts backed by `MachinePartItem`.
- Battery Cell items backed by `BatteryCellItem`.
- Miner's Companion item stacks backed by `MinersCompanionItem`.
- Forestry Companion item stacks backed by `ForestryCartItem`.
- Modular Field Tool heads and rods, including installed heads and rods refined through the Tool Bench Refine tab.
- Job Chips with a job, through the Affix Forge, from a per-chip `work_order_<family>` profile; the Phase Array rejects them, and a chip in a drive bay is not reachable.

Corrupted targets, any trait owner whose `machine_traits` carries a `corruption` record, reject every refinement entry point: the Affix Forge, Exotic Affix Forge (`STATUS_CORRUPTED`), Tool Bench, placed-machine Refinement tabs, Debug Reroller, and a second Volatile Catalyst. `RefinementEngine.apply` checks Corrupted first, then Unique (Uniques accept only `CORRUPT`), then lens and modifier rules. Corruption implicits are stored only in the `corruption` record and listed after affixes in the `CORRUPTION` slot of effective traits. Part implicits on stats the part carries merge like affixes, including hard-gate Processing Level; the rest apply to the host machine. Corrupted tooltips, Affix Forge and Refinement tab readouts, and Jade hide Refinement Potential.

Mirrored targets, any stack or placed machine carrying the `rngtech:mirrored` unit component, reject every refinement entry point: the Affix Forge and its item-stack path (`RefinementMenuSupport.MIRRORED_FAILURE`), placed-machine Refinement tabs (`RefinableMachine.isMirrored`, read from the block entity's kept components), the Phase Cradle (`STATUS_LOCKED`, and `donorAffixes` is empty for a Mirrored Graft donor), the Tool Bench, the Debug Reroller, the Volatile Catalyst, and a second Mirror Catalyst. The component survives placement and breaking through every block loot table that copies `rngtech:machine_traits` (and the Component Recycler tables), and a loaded Job Chip keeps it as `LoadedWorkOrder.mirrored`. The client wraps every RNGTech `inventory` item model (`MirroredItemModels`) so a Mirrored stack resolves to the model reflected across x = 0.5; models drawn by a custom renderer are left alone. `MirroredTooltip` adds Mirrored under the name, and the Affix Forge RP readout shows Mirrored.

Current non-targets are:

- Affix Forge, Exotic Affix Forge, Companion Station, Universal Cable, Energy Connectors, Fluid Connectors, Item Connectors, and Network Connectors.
- Algae Photobioreactor, Wooden Composter, Wooden Dehumidifier, Wooden Dehumidifier Frame, Silica Gel Dehumidifier, Silica Gel Column Casing, Waterproofed Planks, silica gel bead items, and prepared biomass fuel items.
- Machine chassis items.
- Assembled Modular Field Tools; their installed heads and rods are the refinable trait owners and can be refined from the Tool Bench.
- Stacks marked with `rngtech:recycling_stripped`.
- The `rngtech:solid_fuel_burner` category id itself, because concrete burner content uses the four chassis ids.
- Material catalog items, including crushed ore outputs.
- The Primed Cell Core `rngtech:battery_cell` item. The current chargeable gameplay cells use material-specific ids such as `rngtech:iron_battery_cell`.
- Uniques. Their item classes are refinement targets, but every refinement operation, the Exotic Affix Forge, and the Debug Reroller reject Unique rarity and consume nothing.

All successful refinement operations must go through `com.rngtech.rpg.refinement`. Invalid refinement attempts consume no catalyst and no Refinement Potential. Refinement operates on stored rolled affixes and remaining potential; fixed identity behaviors and machine/component base stat profiles are re-derived from the concrete item or placed block and are not stored back as removable affixes.

Generated starting affixes and generated Refinement Potential are independent. Rarity controls starting affix count, while tier eligibility comes from global tier weights, modifier-family tier weights, and component-stage weighting. Component stage is a soft lock rather than a hard cap, except that tier 7 is limited to Stage 8 Exotic targets. Modular Field Tool Heads and Tool Rods use a field-tool tuning variant with `+2` RP and a small component-stage overflow bonus, and can roll flat durability prefixes, percent durability prefixes, Self Repair prefixes, mining-speed suffixes, and attack-speed suffixes; Pick Heads also use a pick-specific profile that can roll rare Vein Miner. Cavitation Rotors also use the shared flat and percent durability prefixes for their stack-stored rotor wear limit. Starting affixes never spend RP.

Crafted trait-bearing outputs are created as unidentified stacks with a stable marker component instead of stored `machine_traits`. This prevents crafting grids and modded crafting previews from revealing the eventual rarity, affixes, or RP while keeping the unidentified stack compatible with strict autocrafting planners. RNGTech recipe metadata exposes both the plain ingredient and the unidentified ingredient variant for trait-bearing recipe inputs. Crafting an unidentified stack by itself marks it for identification; the preview remains unidentified, and the rolled `machine_traits` materialize only when the player takes the identification result. Older unidentified stacks that already carry a hidden seed still identify from that seed. Unidentified stacks are not valid refinement targets until identified.

The current advanced refinement slice uses the existing Affix Forge, Exotic Affix Forge, Tool Bench Refine tab for modular tool parts, or placed-machine Refinement tab. Affix Forge item-stack refinement has no add/upgrade selection UI; it shows a compact RP readout, current-affix list, legal candidate previews, operation-specific RP cost range previews, and optional focus-slot previews. Affix Injector costs `1-8` RP, Affix Upgrader costs `2-6` RP, Greater Affix Upgrader costs `6-10` RP, and Expansion Crystal slot filling still costs `1-18` RP per added affix. Modifier lenses in the focus slot apply a `3x` weight multiplier to matching modifier labels wherever a catalyst other than the Volatile Catalyst picks an affix to add, upgrade, reroll, or remove, without changing tier weights, RP costs, rarity rules, slot limits, or modifier conflicts. Lens previews report current-target matching and still-possible candidate counts, and lens item tooltips expose global tagged affix targets behind Shift. Add, fill, and full-reroll paths can create tier 7 only on Stage 8 Exotic targets when the selected modifier family has a tier 7 range and the target can pay the operation's minimum RP cost; upgrade paths stop at tier 6 except Greater Affix Upgrader can tune capped retunable affixes in-tier. Successful add and upgrade cost rolls remain tier-aware and are capped by the target's remaining RP, so a low-RP target can gamble and may spend all remaining RP. Exotic Affix Forge item-stack refinement is powered and recipe-driven: it can reforge a target as newly generated, refine all affix values in-tier, upgrade a random upgradeable affix, refine or remove a selected rolled affix, or add a legal affix into a selected empty prefix/suffix slot. Exotic Affix Forge operations start from an explicit Apply/Retry button, lock operation controls while running, place successful results in an output slot, and fail with an audible cue if insufficient FE fills the power-failure meter. Successful Exotic Affix Forge operations persist per-stack `totalUses` and per-action counts in `rngtech:exotic_affix_forge_history`, and future FE and catalyst costs scale from that history. The Tool Bench Refine tab is an installed-part entry point for Affix Injector, Ascension Catalyst, and Ascension Matrix on Tool Head and Tool Rod targets. The placed-machine Refinement tabs remain single-catalyst entry points. Corruption storage is implemented through the Volatile Catalyst; the slice does not include phased modifier storage or fracture/instability state storage.

The Debug Reroller is an admin/debug exception for local testing. It does not consume catalysts or Refinement Potential; it rerolls eligible target stack affixes when the item is an existing refinement target and neither Unique nor Corrupted. Fixed identity and authored base profiles remain unchanged after a reroll.

The Debug Chest, Debug Trashcan, Debug Tank, and Debug Battery are also admin/debug exceptions. The Debug Chest uses GUI slots as item templates and lets item automation extract infinite copies without consuming those templates. The Debug Trashcan voids inserted items, filled fluids, and received FE. The Debug Tank stores a fluid template from filled containers, direct bucket interaction, or fluid automation, then exposes infinite extraction of that fluid without consuming the template. The Debug Battery is an infinite FE source that can push or be extracted from up to its selected output cap.

## Challenge Loot Type

`rngtech:challenge` is a loot table type whose conditions read a `ChallengeContext`. Machines and the Forestry Companion roll no loot on their own events, so nothing a machine earns lands in the world. The one shipped table is `rngtech:challenges/work_order`: a Dispatch Terminal rolls it when it lists a job and stores the result on the chip, and a Completed Job Chip without a listed reward rolls it when used; either way the reward goes to the player. [Glyphs](../prds/phase-array.md#glyphs-and-work-orders) come from Work Order rewards (the only default Tier V source), woken Dormant Machines, quests, and `/rngtech glyph give`. `tools/moddex/check-uniques.mjs` fails if another table ships under `loot_table/challenges/`. Its Unique kind is three Prestige-band entries that nest `rngtech:work_orders/unique_reward`, for about 1 Unique per 130 listed jobs (`WorkOrderRuleChecks.rewardRates` holds it between 1 in 200 and 1 in 100). The nested table has one catalog entry per Unique, and each Unique whose part fits a Work Order machine has a second entry at twice the weight behind `rngtech:machine_family`; `tools/moddex/check-work-orders.mjs` holds those families to the machines each Unique host fits. A Unique reward always pays one. The Mirror Catalyst is three plain item entries in the same table, for Tier IV and V jobs, and also always pays one.

The context conditions stay registered for any table of this type: `rngtech:machine_family` (`family`), `rngtech:ascendancy` (`ascendancy`), and the number conditions `rngtech:machine_stage`, `rngtech:recipe_stage`, `rngtech:calibration_stability`, `rngtech:instability`, `rngtech:mastery_level`, `rngtech:order_tier`, and `rngtech:order_prestige`, each with an optional inclusive `min` and `max`. The functions `rngtech:set_order_count` and `rngtech:set_order_tier` size a Work Order reward by the job's tier. A condition never passes outside a challenge roll.

## Verification Baseline

For changes to this surface, run `./gradlew quickCheck` when feasible. For documentation-only edits, run `npm run repo:check` and `mkdocs build --strict`. Run `npm run moddex:check` for source/data consistency. These checks do not replace in-game validation.
